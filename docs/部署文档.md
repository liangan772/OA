# CROA 部署文档

面向运维与实施人员。首次部署按「第三章」走一遍即可。

---

## 一、架构与端口

```
                   ┌──────────────┐
   浏览器 ──:8080──▶│  web (Nginx) │
                   │  静态资源     │
                   │  /api 反向代理│
                   └──────┬───────┘
                          │ :3001（容器内网）
                   ┌──────▼───────┐
                   │    server    │  NestJS
                   └──┬────────┬──┘
                      │        │
              ┌───────▼──┐  ┌──▼──────┐
              │ postgres │  │  redis  │
              └──────────┘  └─────────┘
```

| 服务 | 容器内端口 | 生产是否对外 |
|---|---|---|
| web | 80 | 是（映射 8080） |
| server | 3001 | 否 |
| postgres | 5432 | 否 |
| redis | 6379 | 否 |

---

## 二、环境要求

- Docker 24+，Docker Compose v2（`docker compose version` 能输出版本号）
- 最低 2 核 4G，磁盘 20G 起（PostgreSQL 数据 + 镜像）
- 内网可访问的域名或 IP
- 无需预装 Node / PostgreSQL / Redis，全部在镜像内

---

## 三、Docker Compose 部署（推荐）

### 1. 获取代码

```bash
git clone https://github.com/liangan772/OA.git
cd OA
```

### 2. 配置环境变量

```bash
cp .env.example .env
```

编辑 `.env`，**必须修改这两项**：

```ini
POSTGRES_PASSWORD=一个足够复杂的口令
JWT_SECRET=随机长字符串，可用 openssl rand -hex 32 生成
WEB_PORT=8080
```

生成随机密钥：

```bash
openssl rand -hex 32
```

### 3. 构建并启动

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

首次构建约 3–8 分钟（取决于网络与机器）。查看进度：

```bash
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs -f server
```

`server` 日志出现 `CROA server running at http://localhost:3001/api` 即启动成功。

### 4. 初始化数据

系统启动后库里是空的，需要建组织、编制、人员和流程模板。

**方式一：演示数据（含 8 个账号、2 级单位、4 类流程模板）**

```bash
docker compose -f docker-compose.prod.yml exec server npx ts-node prisma/seed.ts
```

**方式二：空库干净上线**

不执行 seed，直接用管理员账号登录后台手工建：

1. 先建一个管理员账号（见下方脚本）
2. 登录 `/admin` → 编制管理，依次建单位 → 部门 → 编制位 → 任职
3. 流程设计里编排流程模板

创建首个管理员（seed 之外唯一需要的脚本）：

```bash
docker compose -f docker-compose.prod.yml exec server node -e "
const {PrismaClient}=require('@prisma/client');
const bcrypt=require('bcryptjs');
const p=new PrismaClient();
(async()=>{
  const hash=await bcrypt.hash(process.argv[1],10);
  const u=await p.user.upsert({
    where:{account:process.argv[2]},
    create:{account:process.argv[2],name:'管理员',passwordHash:hash,role:'ADMIN'},
    update:{role:'ADMIN',passwordHash:hash},
  });
  console.log('已创建管理员:',u.account);
  await p.\$disconnect();
})()" '你的密码' 'admin'
```

> 注意末尾三个参数：密码、账号。

### 5. 验证

```bash
curl http://localhost:8080/api/health
```

正常返回：

```json
{"status":"ok","db":true,"redis":true,"redisLatencyMs":1,"time":"..."}
```

浏览器打开 `http://服务器IP:8080`，用管理员账号登录。

### 6. 登录后的三件事

1. **改密码**：`/admin` → 系统设置 → 修改密码
2. **确认授权**：跨单位上报需要授权，`/admin` → 跨单位授权，配好「下级单位 → 上级单位」
3. **核对编制**：`/admin` → 编制管理，确认每个部门都有唯一的「正职负责人」编制位（一票否决依赖它）

## 四、配置 HTTPS 与域名

容器内 Nginx 只监听 80。推荐在宿主机或上层网关做 TLS 终止，把流量转发到 `127.0.0.1:8080`。

宿主机 Nginx 示例：

```nginx
server {
    listen 443 ssl http2;
    server_name oa.example.com;

    ssl_certificate     /etc/nginx/ssl/oa.example.com.pem;
    ssl_certificate_key /etc/nginx/ssl/oa.example.com.key;

    client_max_body_size 50m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }
}

server {
    listen 80;
    server_name oa.example.com;
    return 301 https://$host$request_uri;
}
```

> 若前端不是通过根路径访问（如 `https://host/oa/`），需要同步调整 `packages/web/vite.config.ts` 的 `base` 与 Nginx 的 `location`，否则静态资源会 404。

## 五、环境变量说明

| 变量 | 作用 | 默认 | 是否必改 |
|---|---|---|---|
| `POSTGRES_PASSWORD` | 数据库口令，同时用于后端连接串 | 无 | **必改** |
| `JWT_SECRET` | 登录令牌签名密钥 | 无 | **必改** |
| `JWT_EXPIRES_IN` | 登录态有效期 | `7d` | 建议 |
| `WEB_PORT` | 对外 Web 端口 | `8080` | 按需 |
| `DATABASE_URL` | 后端连接串（compose 内自动组装） | — | 由 compose 注入 |
| `REDIS_URL` | Redis 连接串 | — | 由 compose 注入 |
| `TZ` | 时区 | `Asia/Shanghai` | 建议保持 |

修改 `.env` 后需要重建容器才生效：

```bash
docker compose -f docker-compose.prod.yml up -d
```

## 六、数据管理

### 备份

```bash
# 数据库（推荐，逻辑备份）
docker compose -f docker-compose.prod.yml exec -T postgres \
  pg_dump -U croa -d croa --clean --if-exists > backup-$(date +%F).sql

# 数据卷整体备份（含 PostgreSQL + Redis）
docker run --rm -v oa_pgdata:/data -v $(pwd):/backup alpine \
  tar czf /backup/pgdata-$(date +%F).tar.gz -C /data .
```

> 卷名前缀取决于目录名，`docker volume ls` 确认。

### 恢复

```bash
# 停后端避免写入
docker compose -f docker-compose.prod.yml stop server

docker compose -f docker-compose.prod.yml exec -T postgres \
  psql -U croa -d croa < backup-2026-11-04.sql

docker compose -f docker-compose.prod.yml start server
```

### 彻底重置（会丢全部数据）

```bash
docker compose -f docker-compose.prod.yml down -v
docker compose -f docker-compose.prod.yml up -d
```

## 七、升级与回滚

```bash
git pull

# 打标签便于回滚
docker tag oa-server:latest oa-server:backup-$(date +%F)

docker compose -f docker-compose.prod.yml up -d --build
```

- 数据表结构由 `prisma db push` 在启动时自动同步
- **破坏性变更**（删字段/改类型）会失败并中止，此时不要加 `--accept-data-loss`，先备份再评估
- 在途流程实例保存了节点配置与表单快照，模板改版不影响它们

回滚：

```bash
git checkout <上一个提交>
docker compose -f docker-compose.prod.yml up -d --build
```

若新版本已改过表结构，回滚前需要用备份恢复数据库。

## 八、常见问题

**页面 502 / 白屏**

后端没起来。`docker compose -f docker-compose.prod.yml logs server`，常见是数据库连接失败（口令改了但卷里还是旧口令）或 `db push` 报错。

**数据库连不上，日志显示 authentication failed**

改了 `POSTGRES_PASSWORD` 但 `pgdata` 卷是用旧口令初始化的。PostgreSQL 的口令只在首次初始化时写入。要么改回旧口令，要么 `down -v` 重建（会丢数据）。

**health 里 `redis: false`**

Redis 不可用。系统会自动降级为「无缓存直通」：登录、流程、待办全部照常，只失去并发锁与待办计数缓存。单机小规模可接受，多实例部署必须修好 Redis，否则并发推进锁失效。

**构建很慢或 `npm install` 超时**

`docker/server.Dockerfile` 与 `web.Dockerfile` 里的 `npm install` 可加国内镜像：

```dockerfile
RUN npm install --omit=optional --registry=https://registry.npmmirror.com
```

**时间显示差 8 小时**

确认 `.env` 与服务里都有 `TZ=Asia/Shanghai`，并重建容器。

**忘记管理员密码**

用第三章第 4 步的脚本，对同一账号再执行一次即可重置密码并确保是管理员。

**普通账号访问 `/admin` 被跳回**

正常行为。后台仅 `role = ADMIN` 可进，需要在「人员与角色」里提升。

## 九、安全检查清单

- [ ] `.env` 里 `POSTGRES_PASSWORD`、`JWT_SECRET` 已改为随机值
- [ ] `docker-compose.prod.yml` 没有对外暴露 5432 / 6379 / 3001
- [ ] 首次登录后已修改 `admin` 默认密码
- [ ] 已启用 HTTPS，HTTP 强制跳转
- [ ] `.env` 未提交到仓库（`.gitignore` 已包含）
- [ ] 已配置 PostgreSQL 定期备份并有恢复演练
- [ ] 生产环境的 `admin` 账号仅用于管理，日常办理用业务账号
- [ ] 服务器防火墙只放行 80 / 443

## 十一、本地开发环境（非部署）

```bash
npm run install:all
cp packages/server/.env.example packages/server/.env

npm --prefix packages/server run db:dev   # 内嵌 PostgreSQL，端口 55432
npm run db:reset                          # 建表 + 演示数据
npm run dev                               # 后端 3001 + 前端 5173
```

本地库数据目录 `.pgdata` 不进仓库，删除后执行 `npm run db:reset` 即可重建。
