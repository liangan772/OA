## 2026-11-04 · 节点化 OA 系统从零交付

**需求**：统一编制底座 + 四类流程（审议/审批/执行/公示）+ 业务三件套（文档/邮件/收集表）+ 六类通用节点（表态/总结/上报/返回/分配/执行）。用户确认技术路线：NestJS 全栈、多级单位+跨单位协同、本地账号、PostgreSQL + Redis、容器化部署。

**关键设计判断**
- 审议与审批不是两条流程，而是一棵实例树：上报节点在上级创建子实例并挂起，返回/否决回调父实例并把 round+1，重新上报生成新实例。这是整套系统的主心骨。
- 节点是能力组件（NodeHandler: enter/onTask），流程模板负责编排，configSchema 驱动前端配置面板。
- 组织树用单表 + `path` 物化路径 + `rootUnitId` 标记归属单位，跨单位寻址与权限隔离都靠这两个字段。

**踩过的坑（值得记住）**
1. npm workspaces 在 Windows 上做 workspace 软链报 `EISDIR: symlink`，改用两个独立包 + `npm --prefix` 解决。
2. Prisma 的 SQLite provider 不支持 `Json` 标量类型（11 处校验失败），正好切 PostgreSQL 一并解决。
3. `embedded-postgres` 是纯 ESM 包，ts-node(CommonJS) 无法 require，改写成 `.mjs` 用 node 直接跑；且 Windows 中文 locale 会导致 initdb 用 GBK，必须传 `initdbFlags: ['--locale=C','--encoding=UTF8']`。
4. 单位节点的 `rootUnitId` 误继承父单位，导致「区局」被当成市局的下属部门，跨单位判断全部失效。规则是：`type === 'UNIT'` 时 rootUnitId 指向自己。
5. `AssigneeResolver` 漏写 `@Injectable()`，Nest 拿不到 design:paramtypes，注入进来是 undefined，表现为运行时报 `Cannot read properties of undefined (reading 'org')`。
6. 本机 `commit.gpgsign = true` 但无签名密钥，`git commit` 会卡死到超时，必须 `-c commit.gpgsign=false`。

**验证**：`packages/server/scripts/e2e-test.mjs` 36 项断言全通过，覆盖发起→表态→总结→跨单位上报→一票否决→退回补正→第二轮重报→上级通过→父流程联动结束。

**遗留**：附件上传仅前端占位无后端接口；Notification 表已建未接入；表单设计器只做到 JSON 编辑层面，无可视化拖拽；Docker 配置已写但本机无 Docker，未实测构建。
